# ربى

تطبيق أندرويد لمتابعة **الرضاعة الصناعية** وجرعات **علاجات الأطفال**. كل البيانات محلية على الجهاز — بلا حسابات ولا خادم ولا مزامنة.

> ربى أداة تسجيل ومتابعة فقط. لا تقدّم تشخيصاً ولا توصية دوائية، والجرعات والمواعيد يحدّدها الطبيب.

---

## ما ينفّذه التطبيق

| المجال | التفصيل |
|---|---|
| الرضاعة | تسجيل بضغطتين، كميات سريعة قابلة للتخصيص، لوحة أرقام، تعديل وحذف، رضعات سابقة |
| الهدف اليومي | يدوي أو محسوب من الوزن (110 مل/كغ)، بسجل تاريخي فلا يُعاد كتابة الماضي عند تغييره |
| المؤشر | حلقة تقدّم + المتبقي + **توزيع ذكي**: كم رضعة بقيت وكم مل لكل واحدة |
| الجدولة | فاصل زمني قابل للضبط، عدّاد للرضعة القادمة، حالة تأخير، تذكير قبل الموعد |
| العلاجات | ثلاثة أنواع: كورس محدد المدة، دائم، وعند اللزوم |
| أمان الجرعات | تحذير أحمر بتأكيد مزدوج عند جرعة قبل الحد الأدنى أو فوق الحد اليومي |
| السجل | تنقّل بين الأيام، تقويم شهري ملوّن حسب بلوغ الهدف |
| الإحصائيات | أعمدة مقابل خط الهدف، متوسطات، أطول فاصل، منحنى الوزن، التزام العلاجات |
| متعدد الأطفال | تبديل سريع، ترتيب بالسحب، أرشفة تُبقي كل السجلات |
| النسخ الاحتياطي | تصدير/استيراد ملف `.ruba`، ونسخة يومية تلقائية يُحتفظ بآخر سبع منها |
| التحديث الذاتي | قراءة `version.json`، تنزيل بشريط تقدّم، **تحقّق من بصمة SHA-256**، ثم مثبّت أندرويد |

## التشغيل

> ⚠️ **أبقِ المشروع على مسار إنجليزي بالكامل** (هو الآن `F:\Ruba`). أدوات Flutter الأصلية
> على ويندوز — `gen_snapshot` و `impellerc` — لا تقرأ المسارات التي تحوي حروفاً عربية،
> فيفشل البناء برسائل `Unable to read file` و `AOT snapshotter exited with code 255`.
> وصلة المجلد (junction) لا تحلّ المشكلة لأن الأدوات تحلّها إلى المسار الحقيقي،
> و `android.overridePathCheck=true` يُسكت تحذير Gradle فقط ولا يصلح العطل.

```bash
flutter pub get
```

```bash
flutter run
```

المتطلبات: Flutter 3.27+ و JDK 17–21 و Android NDK 27. المشروع مضبوط في `android/gradle.properties` ليستعمل جافا المرفقة مع Android Studio؛ عدّل `org.gradle.java.home` إن كان مسارها مختلفاً عندك.

### أحجام الإصدار

| الأمر | الناتج |
|---|---|
| `flutter build apk --release` | ملف واحد لكل المعماريات — نحو 55 م.ب |
| `flutter build apk --release --split-per-abi --target-platform android-arm64` | نحو 21 م.ب، ويغطّي كل هواتف أندرويد الحديثة |

سكربت `publish-update.ps1` يستعمل الخيار الثاني، لأن الفرق محسوس عند التحديث عبر الشبكة المنزلية.

## مفتاح التوقيع — اقرأ هذا قبل أول نشر

التحديث الذاتي يعمل فقط إذا **وُقّعت كل الإصدارات بنفس المفتاح**. لو تغيّر المفتاح رفض أندرويد التثبيت فوق النسخة القديمة، والحل الوحيد يصبح حذف التطبيق وفقدان بياناته.

أنشئ المفتاح مرة واحدة (اختر كلمات مرور خاصة بك):

```bash
keytool -genkey -v -keystore ruba-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias ruba
```

ثم أنشئ `android/key.properties`:

```properties
storeFile=C:/keys/ruba-release.jks
storePassword=<كلمة المرور>
keyAlias=ruba
keyPassword=<كلمة مرور المفتاح>
```

**احتفظ بنسخة من ملف `.jks` وكلمات مروره خارج الحاسوب.** بدون هذا الملف لا يمكنك إصدار أي تحديث لاحق.

بلا `key.properties` يبني المشروع بمفتاح التصحيح — يعمل للتجربة، لا يصلح للتوزيع.

## نشر تحديث عبر GitHub

التحديث يمرّ عبر مسارين متكاملين:

- **ملف APK** يُرفع كأصل داخل GitHub Release — لأن أصول الإصدارات مصمَّمة للملفات الكبيرة.
- **بيان الإصدار** `updates/version.json` يعيش في الفرع الرئيسي — فيبقى عنوانه ثابتاً ولا يحتاج تعديلاً في الهاتف مع كل نشر:

```
https://raw.githubusercontent.com/mustafaalfahd-max/ruba/main/updates/version.json
```

هذا العنوان مضبوط أصلاً داخل التطبيق كقيمة افتراضية.

**١. ارفع رقم الإصدار** في `pubspec.yaml`. الرقم بعد `+` هو `versionCode` وهو **وحده** ما يقارنه التطبيق:

```yaml
version: 1.1.0+2
```

**٢. انشر:**

```bash
powershell -File tools/publish-update.ps1 -Changelog "إصلاح تنبيه الجرعات","تسريع فتح السجل"
```

السكربت يبني APK، ينشئ الوسم `v1.1.0` ويرفع الملف إليه، ثم يكتب `updates/version.json` بالبصمة ويدفعه. الترتيب مقصود — الملف يُرفع قبل البيان حتى لا يرى التطبيق إصداراً رابطه لا يعمل بعد.

للتجربة بلا رفع: أضف `-DryRun`.

**٣. على الهاتف:** الإعدادات ← التحديثات ← التحقق ← تحديث الآن ← تثبيت. سيطلب أندرويد السماح بالتثبيت من هذا المصدر أول مرة فقط. قد يتأخر ظهور التحديث دقيقة أو دقيقتين بسبب التخزين المؤقت في `raw.githubusercontent.com`.

> المستودع **عام**. التطبيق ينزّل بلا مصادقة، والمستودع الخاص يمنع ذلك ما لم يُدفن رمز وصول داخل APK — وهو ما يُستخرج منه بسهولة. لا توجد أسرار في الكود: مفتاح التوقيع و `key.properties` مستبعدان في `.gitignore`، وبيانات الأطفال لا تغادر الهاتف أصلاً.

### بديل بلا إنترنت

عند الحاجة إلى التحديث داخل الشبكة المنزلية فقط:

```bash
powershell -File tools/serve-updates.ps1 -Port 8080
```

يخدم مجلد `dist` ويطبع عنواناً مثل `http://192.168.1.20:8080/version.json` تضعه مؤقتاً في حقل مصدر التحديث بالتطبيق.

### صيغة `version.json`

```json
{
  "versionCode": 2,
  "versionName": "1.1.0",
  "apkUrl": "https://github.com/mustafaalfahd-max/ruba/releases/download/v1.1.0/ruba-1.1.0.apk",
  "sha256": "9f2c…",
  "changelog": ["إصلاح تنبيه الجرعات"],
  "mandatory": false
}
```

`sha256` اختياري تقنياً لكنه ضروري عملياً — بدونه لا يستطيع التطبيق كشف ملف ناقص أو معدَّل قبل تسليمه للمثبّت.

## النسخ الاحتياطي

ملف `.ruba` هو JSON عادي يحوي كل الجداول:

```json
{ "app": "ruba", "schema": 1, "exported_at": "…", "tables": { "children": [...], "feedings": [...] } }
```

- **التصدير** يفتح ورقة المشاركة — احفظه في التنزيلات، أو أرسله لنفسك، أو ارفعه عبر نفس خادم الشبكة المنزلية.
- **النسخة التلقائية** تُؤخذ مرة كل يوم عند فتح التطبيق (لا في وقت محدد — أندرويد لا يشغّل التطبيق وهو مغلق دون خدمة خلفية)، ويُحتفظ بآخر سبع.
- **الاستعادة تستبدل كل شيء** ولا تراجع عنها، ولذلك تطلب تأكيداً صريحاً. العملية داخل transaction واحدة: إمّا تنجح كاملة أو لا تتغيّر البيانات.

```
lib/

  data/
    db.dart                 مخطط SQLite بـ SQL صريح
    models.dart             النماذج والتحويل من/إلى الصفوف
    repo.dart               طبقة الوصول — كل استعلام مكتوب يدوياً
  state/
    app_state.dart          مصدر الحقيقة الوحيد + القيم المشتقّة
    settings.dart           التفضيلات العامة
  services/
    notifications.dart      تذكير الرضعات والجرعات
    backup_service.dart     التصدير والاستيراد والنسخ التلقائي
    update_service.dart     التحقق والتنزيل والتحقق من البصمة
    report_service.dart     تقرير الطبيب
  ui/
    welcome_screen.dart     الترحيب / إضافة طفل
    shell.dart              الشريط العلوي والتبويبات وزر التسجيل
    tabs/                   الرئيسية · السجل · العلاجات · الإحصائيات
    screens/                الإعدادات · الأطفال · ملف الطفل · نموذج العلاج · تفاصيل العلاج · النسخ · التحديثات
    sheets/                 ورقة الرضعة · حوار الجرعة
    widgets/                البطاقات والأزرار والرسوم
  util/dates.dart           حدود اليوم المنطقي وصياغة التواريخ العربية

  serve-updates.ps1         خادم محلي لتوصيل التحديث عبر الواي فاي
```

### تفصيلتان تستحقان الانتباه

- **بداية اليوم المنطقي**: افتراضياً السادسة صباحاً (قابلة للتغيير). رضعة الثانية فجراً تُحتسب على يوم أمس، وإلا بدا كل يوم ناقصاً ومكتظاً بالتناوب.
- **سجل الهدف**: تغيير الهدف يضيف صفاً جديداً في `goals` بتاريخ سريان، ولا يعدّل الصف القديم — فتبقى إحصائيات الأيام الماضية صحيحة مقابل الهدف الذي كان سارياً حينها.

## غير منفَّذ بعد

- **الوضع الداكن**: التصميم يعرض مبدّل «فاتح / داكن / تلقائي». التطبيق حالياً فاتح فقط، والمبدّل غير معروض بدل تركه زرّاً لا يفعل شيئاً. التنفيذ يحتاج تحويل ثوابت `RC` إلى ألوان تُقرأ من الثيم.
- **تقرير PDF**: يُصدَّر التقرير كملف HTML يُفتح في المتصفّح ومنه «طباعة ← حفظ كـ PDF». توليد PDF مباشرةً يحتاج محرّك PDF وخطاً عربياً مضمَّناً (نحو 3 م.ب إضافية).
